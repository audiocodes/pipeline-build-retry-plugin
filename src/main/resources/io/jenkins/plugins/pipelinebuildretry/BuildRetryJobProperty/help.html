When a build of this Pipeline job ends badly, queue a new build of the job: after a delay, up to a limit, with the same parameters. This is "Retry build after failure" for Pipeline jobs.

The decision is made when the build has ended, after every post block, from its final result, its abort causes, the agents it lost and, optionally, a regular expression found in its log. A retry is a new build with its own number; the in-build retry {} step is a different tool for re-running one block.

In a Jenkinsfile: options { buildRetry(maxSchedule: 3) } (Declarative) or properties([buildRetry(maxSchedule: 3)]) (Scripted).

Some things only a Jenkinsfile can do: stop retries once the build has published or deployed, with buildRetryPointOfNoReturn('why') right before that step; and send a failure notification only when no retry follows, with buildRetryDecision() in post. Both work with the options set on this page.
