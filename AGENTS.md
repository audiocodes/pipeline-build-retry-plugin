# Pipeline Build Retry: notes for agents

A Jenkins plugin that queues a new build of a Pipeline job after a failed build: after a delay, up to a limit, with the same parameters. It is freestyle Naginator's "Retry build after failure" for Pipeline, plus Pipeline-only gates (abort causes, agent loss, Kubernetes pod evidence, failed-stage log scope, a point of no return).

Usage (options, decision order, steps, log lines, limitations) lives in [README.md](README.md). When you write or change a Jenkinsfile that uses the plugin, follow the checklist in README §10 "Jenkinsfile checklist". What the job page can't configure (a point of no return, `buildRetryDecision()`, options computed at run time) is listed in README §1 "What only the Jenkinsfile can do". Plain-text diagrams of the behaviour, one per situation, are in [docs/how-it-works.md](docs/how-it-works.md); when behaviour changes, update the README and that page together.

## Build and test

- JDK 21 (CI also runs 25) and Maven. `mvn verify` runs everything: about 250 tests (several minutes, most start a real Jenkins), Spotless, SpotBugs, the enforcer rules and Javadoc. It must end green, SpotBugs 0, before any commit.
- Run `mvn spotless:apply` before `verify`; Spotless formatting is enforced and fails the build.
- Quick loops: `mvn -Dtest=RetryDecisionTest -Dmaven.javadoc.skip=true verify`. The last run before a commit is a full `mvn verify`.
- The events tests against the newest opentelemetry-api release: `mvn -Potel-latest -Dtest='**/events/*Test' test`. The profile asks Maven for `RELEASE`, so it needs the network or recent metadata in the local repository (`-U` refreshes it); add `-Dopentelemetry-api.version=<version>` to test a chosen one. `OtelRetryEventsTest` fails the run if that API has no `setEventName`. Use `test`, never `package`: an `.hpi` built under the profile declares the newer version as its floor; a full run under the profile fails `OpenTelemetryApiFloorTest` for that reason.
- Behind a TLS-intercepting proxy, Javadoc fails fetching javadoc.jenkins.io: Javadoc runs as its own process and does not inherit `MAVEN_OPTS`. Pass the trust store to it too: `-DadditionalJOption=-J-Djavax.net.ssl.trustStore=<path>`.
- Mutation testing of `core`: `mvn -Pmutation test-compile org.pitest:pitest-maven:mutationCoverage`.
- An `.hpi` to install anywhere: `mvn -Dset.changelist -DskipTests clean package` on a clean, committed tree, since the version comes from the commit. It gives a version such as `12.vb_179e0077e61`; a `999999-SNAPSHOT` build embeds the OS user name in its manifest.

## Architecture

Package `io.jenkins.plugins.pipelinebuildretry`:

- **`core/`**: pure Java, no Jenkins types. `RetryOptions` (options and freestyle-parity defaults), `RetryDecision` (the decision, README §3), `RunSnapshot` (plain-value facts the decision reads), `FailureFacts` (the events' failure class and error fingerprint, built on the decision's own helpers so the two never disagree; the fingerprint's line picking and masking are pure and tested on log fixtures), `DelaySpec`, `LogScanner` (line matching under a timeout, long lines cut in pieces), `ScanPlan`/`ScanResult`. Test it with plain JUnit; this is where decision logic goes.
- **`evidence/`**: turns a `WorkflowRun` into a `RunSnapshot`. `FlowEvidence` reads the flow graph (errors, interruption causes, the agents where errors started, failed stages); `LogScan` reads the console or only the failed stages' step logs; `FailureLine` reads the failing step's arguments and the bounded tail of its own log, for events only; `TerminationReasons` asks clouds why an agent ended, and `KubernetesTerminationReasons` is the Kubernetes source.
- **Root package**: the Jenkins side. `BuildRetryJobProperty` (`buildRetry(…)`, the only place options are set), `BuildRetryListener` (decides in `onCompleted`, queues the retry), `AbortPreviousGuard` (a starting build cancels older queued retries under `abortPrevious`), `CancelledRetryListener` (reports a waiting retry cancelled by anyone else; the plugin's own cancels go through its `cancel` so they are not reported twice), `BuildRetryGlobalConfiguration` (the off switch and the default regexp timeout), the Cause, the env contributor and the run Actions below.
- **`steps/`**: `buildRetryDecision()` (decides now with the current result, records the preview, returns it) and `buildRetryPointOfNoReturn('why')`.
- **`events/`**: monitoring events (README §7 "Events"). `RetryEvents` is the sink extension point, `OtelRetryEvents` owns one small OTLP/HTTP logs exporter built from the opentelemetry-api plugin's SDK (bounded queue, its own endpoint and token settings; the full opentelemetry plugin is deliberately not used, to keep controller load predictable); `BuildRetryEvents` in the root package builds them; `JobConfigEvents` sends each configured job's settings (hourly, at startup, on a save that changes them, on delete or rename), and must never send the regexp text or any hash of it: a short pattern can be guessed back from a plain hash. The same holds for `neverRetryPatterns`: logs, reasons and events name a pattern by its 1-based index or count, never its text. Sending is off unless `sendEvents` is on (`JobConfigEvents` also needs `sendJobConfig`, and turning that off sends no removals), and a failing sink never changes a decision. `OtelRetryEvents` also filters the SDK's JVM-wide `HttpExporter` logger, by name, to turn SEVERE export failures into one-line warnings; after an opentelemetry-api bump, `OtelRetryEventsSenderTest#aDeadCollectorDoesNotSlowTheRetry` goes red if that logger was renamed. Rules for `events/`: only public SDK classes (`SdkLoggerProvider`, `BatchLogRecordProcessor`, `OtlpHttpLogRecordExporter`, `Resource`, `LogRecordBuilder`); never `GlobalOpenTelemetry`, autoconfigure, SPI lookups or `ReconfigurableOpenTelemetry.configure()`, which would take over the controller-wide instance the opentelemetry plugin owns; no OpenTelemetry type outside `OtelRetryEvents` (`NoOpenTelemetryTypesTest`). The build compiles and tests against the floor (`opentelemetry-api.version`), where `setEventName` (OpenTelemetry 1.50+) is absent, so also run the events tests against the newest release with `mvn -Potel-latest -Dtest='**/events/*Test' test` (see Build and test): only there is the event-name path tested. After a new opentelemetry-api release, run both and the live dead-collector check.
- **`dashboards/`**: the Grafana dashboard for the events, a Loki-only JSON edited in Grafana and copied back. Keep it generic: no data source uid (the `loki` variable's `current` stays `{}`), host or company name.
- **`delay/`**: the typed delays (`fixedDelay`, `progressiveDelay`, `listDelay`) bound by the job property.

Run Actions, all persisted in `build.xml`:

- `RecordedDecisionAction`: the preview the decision step recorded, with the options and facts behind it.
- `DecidedAction`: the end decision and what became of it; its presence stops a second decision.
- `RetryScheduledAction`: the shared marker "a retry is armed or queued for this build". Check it before arming and set it when arming, so two retry mechanisms never both retry one build.
- `PointOfNoReturnAction`: the build passed a point after which it is never retried.
- `BuildRetryAction`: the build's place in its retry chain, and its badge.

## Key decisions

Each is deliberate; change one only with the maintainer's agreement, and keep the README in step.

- **Pipeline only, new builds only.** The plugin acts on `WorkflowRun`s of jobs that carry `buildRetry`, multibranch branch jobs included. Freestyle stays with Naginator, and in-build retry stays with the `retry` step and other plugins. This no-overlap line is part of the plugin's case for being a separate plugin.
- **Decide at the end.** The listener decides on the final result, after every `post` block. The decision step's recorded preview is reused when the final result equals the recorded one; otherwise the listener decides again and logs why. The options in force are the job property as it is at the build's end, or the ones the step recorded.
- **All state in Jenkins' own files.** Retry state lives in run Actions (`build.xml`) and queue items (`queue.xml`), so a controller restart keeps every waiting retry. The listener and the guard hold no state in memory; keep it that way.
- **Freestyle parity.** Option names and defaults follow freestyle Naginator: `maxSchedule` 0 means unlimited, the progressive delay is 300/10800, and a FAILURE retries by default unless a regexp gate stops it. An OOM-killed agent only removes the agent-loss evidence; it adds no new gate.
- **Independent of Naginator.** No dependency on Naginator, no `NAGINATOR_*` variables, own Cause, Action, env (`BUILD_RETRY_*`) and log prefix `[Build Retry]`. Code derived from Naginator keeps its attribution in [NOTICE.md](NOTICE.md) and the file headers.
- **Dependencies.** Hard: workflow-job, workflow-api, workflow-step-api, structs, credentials, plain-credentials. kubernetes and opentelemetry-api are optional, each reached only through one `@Extension(optional = true)` class (`KubernetesTerminationReasons`, `events/OtelRetryEvents`). Classes of other plugins are matched by name in `evidence/ClassNames`, with no dependency, so they may be absent.
- **credentials is pinned to the oldest supported version** (1506) for the same reason; `OtelRetryEventsSenderTest` checks it. opentelemetry-api is pinned to 1.39.0-11, the oldest release that bundles the logs SDK; use only API methods it has, or reach newer ones through a method handle as `setEventName` is. An optional dependency is still version-checked when installed: an older one installed stops the whole plugin from loading.
- **kubernetes is pinned to the oldest supported version** (4540), not the bom's, so the built plugin also loads on controllers that run 4540. `KubernetesTerminationReasonsTest` checks the tests run against that version. It calls the source directly because `TerminationReasons.byAgent` swallows a `LinkageError`, which would hide a missing API as empty reasons.
- **The off switch.** `enabled` in the global configuration (JCasC `unclassified: buildRetry: enabled:`). Off means no decision and no new retry; retries already queued stay. The documented way to flip it is the setter in the script console (README §7), because saving the System page saves every setting on it again.
- **Every version needs a controller restart**, since Jenkins does not swap a loaded plugin. Anything an administrator may need in an incident, such as the off switch, belongs in the first version a controller installs.
- **Branches and publication.** `master` is internal development. The public repository (`github.com/audiocodes/pipeline-build-retry-plugin`) gets only `main`, a line of clean snapshot commits that shares no history with `master` and carries no review trailers; outside pull requests merged there are re-applied to `master`. Installable releases are built from `main` only. The plugin is not hosted by the Jenkins project yet, so docs point to GitHub releases and GitHub private vulnerability reporting.
- **Baseline:** core 2.555.3, `bom-2.555.x`, parent POM 6.2236; these are also the Jenkins hosting checker's minimums.

Out of scope for v1, planned later: restart from the failed stage (v2), and a startup sweep for builds that never reach `onCompleted` (README §9).

## Rules

- **Generic names.** Code, tests, docs and commit messages name no company, product, project, controller or host. Examples use placeholders such as `CONTROLLER` and `ADMIN`. The only exceptions: the copyright holder in `LICENSE.md` and the file headers, the repository URLs, and the author credit (`pom.xml` `<developers>`, README, `ACKNOWLEDGEMENTS.md`).
- **Test first.** Write the failing test, see it go red, then change the code. After the change, break each new branch by hand once and check that a named test goes red.
- **Web methods.** Every `do*` method is `@POST` and checks permission through `FormText.canConfigure` (or `Jenkins.ADMINISTER` for global settings). `WebMethodSecurityTest` enforces this.
- **Help and docs are tested.** `HelpFilesTest` needs a help file for every form field, Pipeline argument, step and option. The README and `help-enabled.html` must carry the exact setter lines, which a test runs. Renaming a class or option means updating those files.
- **Jelly stays CSP-clean.** Put scripts and styles in separate files and use no `on*` attributes; the hosting checker rejects inline `<script>` and `<style>` and warns on `on*`.
- **Comments are one line**, saying what the code cannot: a constraint or a non-obvious reason. Longer reasoning goes in the commit message.
- **Live tests** run only on a dedicated test controller, never a production one: install the `.hpi` (restart), then run demo Pipeline jobs that fail, time out, get stopped, or lose their agent pod. Record each run's build numbers and log lines.
- Commits use the Conventional Commits style (`feat:`, `fix:`, `docs:`, `build:`, `test:`), with a subject under 75 characters and a body that says why.
